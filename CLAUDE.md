# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`AGENTS.md` holds the full style, naming, and change-etiquette rules for this repo. Follow it; this file covers commands and architecture.

## What this is

mdit is a desktop Markdown editor/viewer: Go 1.27 + Wails v2 backend, Vanilla JS + Alpine.js + Tailwind + Vite frontend. Split pane: source editor on the left, live preview (`marked` + `DOMPurify`) on the right, with tabs, undo/redo, search, and scroll sync.

## Commands

- Dev (Go backend + Vite dev server): `make dev` (or `wails dev`)
- Production build: `make build` (or `wails build`). Output goes to `build/bin/`
- Linux with WebKitGTK 4.1 (Fedora and other current distros): `wails build -clean -tags webkit2_41`
- Frontend-only build: `npm --prefix frontend run build`. Always use `npm --prefix frontend`, not `cd frontend`
- Toolchain: Go and the Wails CLI are pinned in `mise.toml`; run `mise install` once
- Go tests: `mise exec -- go test -tags webkit2_41 ./...` (drop the tag on systems with WebKitGTK 4.0)
- Single test: `mise exec -- go test -tags webkit2_41 ./... -run '^TestName$'`
- Format Go: `mise exec -- gofmt -w <files>`

Tests live in `app_test.go` and `localimages_test.go`; there is no lint config. `testdata/local-image.md` is a manual check for local images. To verify frontend changes, run the Vite build. When file handling changes, check open/save/cancel and the preview by hand.

## Architecture

**Backend (package `main`, two files):**
- `main.go` embeds `frontend/dist` (so the frontend must be built before `go build`) and `build/appicon.png`. It scans CLI args for the first `.md`/`.markdown` path (made absolute) and passes it to `NewApp` as the startup file. It binds `App` to the frontend.
- `app.go` defines `App`, which exposes `OpenFile()`, `SaveFile(content, currentPath)`, `SaveFileAs(content, currentPath)`, `ReadFile(path)` and `GetStartupFile()` to JS. Both save paths go through `writeMarkdown` (`.md` default, `0o644`). `OpenFile` returns `nil, nil` on cancel. `SaveFile` returns `""` on cancel, only shows a dialog when `currentPath` is empty, and appends `.md` when the path has no extension. `lastOpenDir` remembers the last dialog directory.
- Startup file flow is pull-based: the frontend's `openStartupFile()` (called from Alpine `init`) calls `GetStartupFile()`, which returns the CLI file once and then clears it. Don't switch back to emitting an event on DOM ready; the frontend isn't listening yet at that point and the file gets lost. A missing/unreadable file is reported as an error and shown in a toast.
- File associations: `wails.json` `info.fileAssociations` (`.md`, `.markdown`) feed the Windows NSIS installer (`build/windows/installer/wails_tools.nsh`, icon generated by Wails from `build/markdown-doc.png`) and macOS `build/darwin/Info.plist`. Windows passes the file as a CLI argument. macOS does not: Finder calls `Mac.OnFileOpen` → `App.openFileFromOS`, which stores the path as the startup file until the frontend has called `GetStartupFile()`, and afterwards emits an `open-file` event (`open-file-error` on failure) that the frontend turns into a new tab. Linux associations live in the desktop entry in `packaging/linux/`.
- Single instance: `main.go` sets `SingleInstanceLock` with `instanceID` (`instance_id.go`; `instance_id_dev.go` under the `dev` build tag so `wails dev` never forwards to an installed mdit). A later launch exits (code 1) after Wails passes its args and working directory to `App.onSecondInstanceLaunch`, which reuses `markdownPathFromArgs` + `openFileFromOS` and raises the window. On Linux Wails uses the D-Bus name `org.wails_app_<instanceID with . and - as _>.SingleInstance`; the Flatpak manifest must keep a matching `--own-name`, or Flatpak silently falls back to separate instances. Changing `instanceID` means updating that line too.
- `go vet`/`go test` compile the WebKit bindings, so on WebKitGTK 4.1 systems pass `-tags webkit2_41` (e.g. `mise exec -- go test -tags webkit2_41 ./...`). `app_test.go` covers argument parsing.

**Frontend (`frontend/src/`):**
- Layout: `main.js` only bootstraps (styles, fonts, `window.markdownViewer`, template, `Alpine.start()`); `template.js` holds the whole HTML template; `viewer/` holds the Alpine component split into parts (`core.js` state/init, `tabs.js`, `utility.js`, `view.js`, `editing.js`, `files.js`, `scroll.js`, `links.js`, `search.js`, `palette.js`, `feedback.js`, `keyboard.js`, plus `constants.js`); `preview/render.js` is the Markdown → HTML pipeline; `lib/` has path, preference and editor-measuring helpers.
- `viewer/index.js` merges the parts with `compose()` (`viewer/compose.js`), which copies property descriptors so getters stay getters. Never merge parts with object spread: that evaluates `isUtility`, `showEditor`, `commands` and the other getters once and freezes them. Parts call each other through `this`.
- Holds all UI state and behavior in one Alpine component, `window.markdownViewer`: tabs, per-tab undo history, command palette, view mode (`editor`/`split`/`preview`), outline, find, and scroll sync. There is no menu bar; every action is a palette command (the `commands` getter) and most have a shortcut in `handleGlobalKeydown`.
- The entire HTML template is a template string (`template.js`) assigned to `#app.innerHTML` in `main.js` before Alpine starts.
- The backend is reached through `window.go.main.App` via the `backendApp()` helper. Runtime APIs (`BrowserOpenURL`, `ClipboardSetText`, `Quit`) come from the generated `frontend/wailsjs/runtime`.
- There are two kinds of tabs: file tabs (can be dirty, can be saved) and utility tabs (the cheat sheet and about tab, loaded with `?raw` from `src/assets/markdown/*.md`). Utility tabs are preview-only; "Edit a copy" turns one into a new file tab. They close through special preview links (`#close-cheatsheet`, `#close-about`), which `handlePreviewClick` intercepts. Other links open in the system browser.
- A file tab is dirty when `markdown !== savedMarkdown` (see `updateDirty`), so undoing back to the saved text makes it clean again.
- The outline comes from `marked.lexer` top-level h1–h3 tokens; each item's source line is computed from token `raw` text, and its index matches `:scope > h1, h2, h3` in the preview. Outline jumps pause scroll sync (`syncOrigin = 'outline'`) while both panes scroll.
- Find highlights preview text with the CSS Custom Highlight API (`::highlight(search)`), never by rewriting the sanitized HTML.
- Preview pipeline in `renderNow` (`viewer/editing.js`): `renderMarkdown` (`preview/render.js`: `marked.parse` → `DOMPurify.sanitize`, = `exportHtml`, used by "Copy rendered HTML") → `decoratePreview`, which adds preview-only chrome on an inert `<template>` with DOM APIs only: code block headers (language label via CSS `attr(data-lang)`, copy button handled in `handlePreviewClick`), syntax highlighting (`preview/highlight.js`: highlight.js core with registered common languages, output re-sanitized; token colors are `--hl-*` theme variables in `style.css`) and local image sources.
- Local images: `resolveLocalImages` rewrites non-remote `<img src>` to `/mdit-local?path=<absolute path>`, resolving relative paths against the open file's folder (unsaved documents can't resolve relative images). `localimages.go` serves that route as asset-server middleware, only for absolute paths to regular files with an image extension (tests in `localimages_test.go`). `file://` URLs are stripped by DOMPurify and stay unsupported.
- View mode, sidebar, theme and word wrap persist in `localStorage` (`mdit.ui`); reads and writes go through `loadStored`/`saveStored` in `lib/prefs.js`, which swallow storage errors.
- `viewer/session.js`: recent files (`mdit.recent`, max 10, shown as palette commands) and session restore (`mdit.session`: saved file tabs + active path, from the `sessionSnapshot` getter). `startSession()` restores before opening the CLI/OS startup file and only starts saving the session after restoring, so the initial empty state never overwrites it.
- External changes: `watcher.go` watches the parent folders of open files with fsnotify (editors and git replace files by rename), debounces 200 ms and emits `file-changed` / `file-removed`. `viewer/watch.js` keeps the watch set in sync via `SetWatchedFiles` (from the `watchedPaths` getter) and reloads clean tabs as an undo step; a change equal to `savedMarkdown` (e.g. our own save) is ignored, dirty tabs ask first.
- Unsaved-close warning: the `unsavedCount` getter is pushed to `App.SetUnsavedChanges`; `lifecycle.go` `beforeClose` (wired as `OnBeforeClose`) shows a native question dialog when it is above zero. Linux/Windows return "Yes"/"No", macOS returns the button label, see `confirmsQuit`.
- Styles: Tailwind v4, CSS-first. There is no `tailwind.config.js`. Colors are CSS variables on `:root` / `:root[data-theme='light']`, mapped to utilities (`bg-surface`, `text-muted`, `border-line`, `text-accent`, …) by `@theme inline` in `src/style.css`; use those tokens, not raw slate/cyan classes, so both themes work. Utilities live inline in the template. Component classes live in `src/style.css` under `@layer components`. Fonts (Inter, JetBrains Mono) are bundled via `@fontsource` packages so the app works offline.
- `mockups/modern-ui.html` is the standalone design mockup this UI was built from (CDN-loaded, not part of the build).

**Generated / build artifacts:** `frontend/wailsjs/` is regenerated by `wails dev`/`wails build`, so don't hand-edit it. `frontend/dist/` is a Vite build artifact.

**Release:** `.github/workflows/release.yml` runs on `v*` tags (publishes a GitHub release) or manually (artifacts only). Jobs: `linux` builds the binary once on ubuntu-24.04 and hands it to `appimage` (appimagetool 1.9.1, WebKitGTK not bundled) and `flatpak` (GNOME 51 runtime, manifest in `packaging/flatpak/`, packages the prebuilt binary rather than building in the SDK); `windows` builds the NSIS installer + portable zip; `macos` builds a universal `.app` as dmg + zip. `packaging/set-version.mjs` writes the tag into `wails.json` `info.productVersion` before each build. The Flatpak/AppImage app ID is `io.github.Nilpointer.mdit`; its desktop entry, AppStream metainfo and square icons live in `packaging/linux/`. WebKitGTK 4.1 must stay available in the chosen GNOME runtime (it is in 49–51).

## Style note

`AGENTS.md` says frontend JS doesn't use semicolons, but the existing frontend modules (`main.js`, `viewer/`, `preview/`, `lib/`) use them throughout. Match the surrounding code when editing, and don't reformat existing lines.
